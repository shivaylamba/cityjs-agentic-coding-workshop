# 06 · Compare guided and bounded autonomous work

11:05–11:20 · 15 minutes

Implement agenda export, compare supervision styles, and score the evidence rather than the prose.

## Concepts

Autonomy is a delegation boundary, not a switch that removes responsibility. A bounded task has a goal, allowed changes, a stopping condition and a validation contract.

We compare the same export requirement from the same committed base. Half the pairs use guided checkpoints; half use one bounded request. Keep the model and environment the same where possible and record differences.

This is a classroom experiment, not a scientific product ranking. Network latency, prior context, models and pair experience can affect outcomes. A small sample does not establish which tool is universally better.

## Understand before building

### Guided work versus bounded autonomy

Guided work uses human checkpoints before and during implementation. Bounded autonomy delegates a complete small task with explicit scope, checks and stop conditions. Both retain normal client permissions and human review.

```text
Goal: agenda export.
Allowed: export helper, tests, smallest parent wiring.
Forbidden: new dependencies, spec changes, push or deploy.
Stop: contradiction, blocked environment or time limit.
```

The room splits into treatments from checkpoint-05. Guided pairs approve a plan and inspect an intermediate diff. Autonomous pairs give the bounded contract once. Do not run both treatments on every laptop.

**Check your understanding:** Does autonomy mean the agent can expand requirements?

**Expected reasoning:** No. It must stop or ask at the agreed boundary.

### What browser export actually does

Plain-text export turns selected data into a text string, wraps it in a Blob and triggers a browser download. A temporary object URL refers to that Blob and must be released after use. Empty selection produces feedback without a download.

```text
Selected sessions → sort by start minute, then ID
→ format time + exact title + room
→ Blob → object URL → download cityjs-agenda.txt
→ release object URL after use
```

This is a flow diagram, not an API implementation. Inspect the generated helper and actual downloaded file. Quotation marks, commas and non-ASCII text should remain intact. Keep it a text export; do not add a server.

**Check your understanding:** Does clicking Export prove the file content is correct?

**Expected reasoning:** No. Open or assert the downloaded content and compare it to the selected agenda.

### Score evidence rather than confidence

Use the same acceptance criteria and baseline for both treatments. Record time, interventions and results. Different context, models or network conditions limit the comparison. Missing cost or token information is not measured.

```text
Correctness: 0–5
Edge cases: 0–3
Review evidence: 0–2
Also record: starting SHA, treatment, time, interventions
```

Score the real file, empty case and checking evidence. A fluent completion summary adds no points. This is a practical comparison of supervision choices, not a benchmark that ranks every model.

**Check your understanding:** What do you record when the timebox ends before completion?

**Expected reasoning:** The completed evidence and unfinished work, not an assumed eventual success.

## Steps

### 1. Start from the same baseline

Each pair uses checkpoint-05 as the starting point. Assign guided or bounded-autonomous treatment across the room; do not run both concurrently on every laptop. Create a feature branch and record the starting SHA.

```sh
git switch -c experiment/export
git rev-parse HEAD
```

### 2. Build the same feature

Export the selected agenda to cityjs-agenda.txt, ordered by start minute then ID, with time, title and room. An empty agenda produces a visible message and no download. Use a Blob/download link, release the object URL after use, and add no dependencies. Guided pairs review a plan before editing; autonomous pairs use the complete task contract once.

### 3. Score actual results

Use the downloadable scorecard: core correctness 0–5, edge cases 0–3, review evidence 0–2. Record interruptions and elapsed time. Check the exported contents manually and via tests. Compare pairs rather than asking everyone to run two expensive trials.

### 4. Save the useful result

Keep the reviewed export implementation, fix observed defects within scope and commit. If incomplete, record it honestly and continue review using the reference export helper. Never silently mark a timeout as success.

## Editable task prompt

```text
Implement the agenda text export acceptance criteria from this lab on the current branch. Read AGENTS.md and docs/spec.md first. You may edit only the export helper, its tests and the smallest App wiring needed. No dependencies, pushes, merges, deployments or spec changes. Sort by start minute then ID; preserve exact titles; include time and room; show a clear message without downloading for an empty agenda; release download resources. Work independently, run the real relevant checks, and inspect the result. Stop at a contradiction, blocked environment or the host time limit. Report changed files, commands/exits, acceptance evidence and remaining risks. Do not claim unrun browser checks passed.
```

## Evidence

- The downloaded text is ordered and matches actual selected sessions.
- An empty agenda produces no download; unusual titles remain intact.
- The scorecard records starting SHA, treatment, model if known, time, interventions and unmeasured fields.
- The agent respects the no-deploy/no-new-dependency boundary.

## Experiment

Give the export task a title containing a comma, quotation marks and a non-ASCII character. Does plain text preserve it? Compare an earlier vague request with the bounded request, but label it a qualitative observation rather than a controlled benchmark.

## Recovery

If your agent times out, stop it, inspect its current diff and score only the completed evidence. The reference export function is in the recovery app. Do not spend the next review block waiting for a model response.
