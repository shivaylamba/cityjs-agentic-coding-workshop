# Lab 07: Find a bug and add a release gate

20 minutes

A regression test catches a bug when it returns. CI runs checks on a separate runner. We will prove our checks reject a broken candidate.

## What to do

### 1. Reproduce the boundary bug

On a disposable change, replace < with <= in the overlap rule. Back-to-back sessions should now be incorrectly rejected. Show the failing test; restore the correct rule.

### 2. Review, repair and check

Ask a fresh agent chat to review your change against checkpoint-05. Verify a concrete finding before accepting a fix. Keep a regression test and run the checks.

```text
git diff checkpoint-05...HEAD
npm run typecheck
npm test
npm run build
npm run test:e2e
```

### 3. Prepare the review packet

Copy the CI template to .github/workflows/ci.yml. Update README.md, docs/pr-summary.md and docs/release-evidence.md. If GitHub access is ready, open a draft PR in your own repo and inspect CI; otherwise record remote CI NOT RUN.

## Files you need

- [CI template](https://cityjs-agentic-coding-attendees.shivaylamba.chatgpt.site/downloads/ci.yml)
- [Release evidence template](https://cityjs-agentic-coding-attendees.shivaylamba.chatgpt.site/downloads/release-evidence.md)

## You are done when

- A check fails with the bug and passes after repair.
- Your review packet records actual results; pending CI is not called passed.

## Try one change

Run release-check on a failing candidate. Does it refuse to call the candidate ready?

## Prompt help

```text
Review the current change against checkpoint-05 without editing first. Prioritise correctness and regressions in overlap handling, corrupt storage, composed filters, exports and accessibility. Return only actionable findings with file/line, trigger, impact, acceptance ID and reproduction. Distinguish confirmed findings from suspicions. Do not invent test output. After I choose a confirmed finding, add a failing regression, implement the smallest fix, run checks, and update release evidence and README to match actual capabilities.
```

## Stuck?

If no reviewer finding is valid, use the packet’s deliberately faulty overlap example and add a new boundary assertion. If CI cannot run remotely, execute the equivalent local commands and mark remote CI NOT RUN; do not fake a green badge.
